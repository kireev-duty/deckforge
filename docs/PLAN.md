# План: «Цифровой дизайнер презентаций» (хакатон ЛЦТ 2026, кейс VK Tech)

## Контекст

Соло-участник, 2 недели, стек Python (FastAPI) + Streamlit, инференс через внешний API (открытые модели ≤35B, Apache 2.0/MIT). Нужно сдать: репозиторий, документацию (README / ARCHITECTURE / MODELS / AUDIT), питч (≤7 мин, шаблон ЛЦТ2026), работающий прототип, видео-демо и 9 презентаций (1 контент × 3 шаблона × 3 варианта вёрстки).

Разведка датасета (важно для архитектуры):
- `theme.xml` в шаблонах **не отражает** реальную дизайн-систему: у VK WorkSpace в теме дефолтные Office-цвета (`#4472C4`), а на слайдах — `#0077FF`, `#00AEE8`, `#212121`; в теме шрифт Arial, реально — встроенный **Play**. Вывод: токены нужно извлекать из **фактического использования** на слайдах (гистограммы цветов/кеглей/шрифтов) + из темы как fallback.
- Имена лейаутов хаотичны и дублируются (`1_Титульный слайд`, `3_Титульный слайд`, `14_Контент`, `DEFAULT`) → классифицировать лейауты по **геометрии плейсхолдеров**, не по именам.
- Шаблоны — «деки-примеры» на 29–55 слайдов: каждый слайд — образец композиционного паттерна. Клонирование XML слайда-образца с подменой контента даёт нативные объекты в .pptx и высокую верность стилю.
- Контент-пакета нет — делаем синтетический. Шаблон ЛЦТ2026 (Montserrat, `#FF0053`, 23 лейаута, 3 диаграммы) — идеальный **holdout «неизвестный шаблон»** для самопроверки.

## Выигрышная концепция (чем отличаемся)

1. **Template DNA** — шаблон парсится в единый JSON-документ дизайн-системы: палитра с ролями (bg / text / accent / muted) по частоте использования, типографическая шкала с ролями (H1/H2/body/caption), сетка и поля (кластеризация bbox всех фигур), логотипы/колонтитулы (фигуры, повторяющиеся на N слайдах в одной позиции), **архетипы слайдов** (title / section / bullets / two-col / kpi / chart / table / image+text / quote / closing), каждый со «слотами» (какие плейсхолдеры, лимиты символов, допускает ли картинку/график). Детерминированная геометрия + VLM-разметка рендеров для семантики.
2. **Exemplar cloning** вместо генерации с нуля: для каждого слайда выбирается слайд-образец из шаблона, клонируется, слоты заполняются. Никаких «примерно похожих» слайдов — стиль воспроизводится буквально.
3. **Аудит внутри пайплайна с авто-фиксом**: детерминированные проверки (XML-геометрия, палитра, шрифты, плотность) → авто-фикс (уменьшить кегль, разбить слайд, сменить архетип) → VLM-проверки по 11 вопросам на PNG → пользователь выбирает, что исправить, в UI. Регенерация только проблемных слайдов.
4. **Три варианта вёрстки** как версионируемые «стратегии» (файлы конфигов): `executive` (плотно, таблицы, 8–10 слайдов), `narrative` (одна мысль на слайд, большие цифры, 12–15), `visual` (графики/иконки/картинки, 10–12). Ось различий — плотность + способ визуализации; обоснование в ARCHITECTURE.
5. **Скиллы и агенты как файлы с версиями** (`skills/<name>/v1.2/skill.yaml + prompt.md + schema.json`), реестр, и `manifest.json` в каждой сгенерированной колоде с провенансом (какие версии скиллов/моделей/стратегий использовались). Прямое попадание в п.4 ТЗ и «промпты не зашиты в код».
6. **Dogfooding**: питч для защиты сгенерирован самим сервисом по шаблону ЛЦТ2026 (с ручным fallback).

## Архитектура (границы слоёв = пакеты)

```
deckforge/                     # имя условное
  core/ir.py                   # SlideIR / DeckIR (pydantic) — единая промежуточная модель
  parsing/                     # pptx → TemplateDNA (python-pptx + lxml + LibreOffice-рендер + VLM)
    extract_tokens.py          # цвета/шрифты/кегли из использования; тема как fallback
    layout_classifier.py       # архетипы по геометрии плейсхолдеров
    exemplars.py               # индекс слайдов-образцов со слотами
  content/                     # бриф + контент-пакет → DeckOutline (структура, тексты, данные для графиков)
  layout/                      # DeckOutline + TemplateDNA + strategy → DeckIR (подбор образца, fitting текста)
  render/                      # DeckIR → .pptx (клонирование образцов, нативные chart/table/icons)
    pptx_writer.py, charts.py, tables.py, icons.py, images.py
  audit/                       # deterministic/*.py + contextual/*.py → AuditReport; autofix.py
  export/                      # pptx → pdf (soffice headless), DeckIR → html (свой рендер)
  llm/                         # OpenAI-совместимый клиент; text / vision / image; retry, JSON-mode
  skills/                      # ВЕРСИОНИРОВАННЫЕ промпты/конфиги сервиса (не код!)
    registry.yaml
    outline_writer/v1/{skill.yaml,prompt.md,schema.json}
    slide_filler/v1/..., template_tagger/v1/..., audit_judge/v1/..., image_prompter/v1/...
  strategies/{executive,narrative,visual}.yaml
  api/                         # FastAPI: /templates, /generate, /audit, /export, /jobs
  ui/app.py                    # Streamlit: загрузка шаблона → бриф → 3 варианта → аудит с чекбоксами → экспорт
  cli.py                       # typer: parse / generate / audit / export / run --config run.yaml
tests/                         # pytest: парсинг 3+1 шаблонов, аудит на синтетических «плохих» слайдах, e2e
configs/run.example.yaml       # «запуск конфиг-файлом»
docs/{README,ARCHITECTURE,MODELS,AUDIT}.md
examples/content_pack/         # синтетический контент-пакет (бриф.md, данные.csv/json, product.md)
examples/output/               # 9 колод + holdout
```

Ключевые технические решения:
- Рендер слайдов → PNG: `soffice --headless --convert-to pdf` + PyMuPDF. Используется и в парсинге (VLM-разметка), и в аудите, и для превью в UI, и для PDF-экспорта.
- Text fitting без PowerPoint: оценка ширины через Pillow `ImageFont` (шрифты Play/Montserrat вытащить из `ppt/fonts/` или брать метрики Arial как приближение) → детерминированная проверка «текст не влез» + авто-уменьшение кегля по шкале шаблона.
- Графики — нативные `python-pptx` chart (перекрашенные в палитру DNA), таблицы — нативные, иконки — Tabler Icons (MIT) SVG → PNG в цвете акцента, SmartArt-подобные схемы — группы автофигур по шаблонам (process / cycle / pyramid).
- Картинки (со звёздочкой): FLUX.1-schnell (12B, Apache 2.0) или Qwen-Image (20B, Apache 2.0) через API; промпт с цветами палитры; вставка в image-слот с crop под аспект (детерминированная проверка пропорций).
- HTML-экспорт — свой рендер из DeckIR (абсолютное позиционирование, те же координаты в px), не через LibreOffice.
- Модели (проверить актуальные ID/лицензии на HF перед фиксацией в MODELS.md): LLM — Qwen3-32B (или новее из линейки Qwen3.x ≤35B; запасной вариант Mistral-Small-3.x-24B, Apache 2.0); VLM — Qwen3-VL-32B-Instruct (запасной Qwen2.5-VL-32B); T2I — FLUX.1-schnell / Qwen-Image. Всё через один OpenAI-совместимый клиент с `LLM_BASE_URL`/`LLM_MODEL` в `.env`, чтобы в топ-10 переключиться на инференс VK одной переменной.
- Бюджет времени ≤5 мин/колода: outline — 1 вызов LLM, заполнение слайдов — батч по 3–4 слайда параллельно, аудит VLM — параллельно по слайдам. Логировать тайминги в manifest.

## Как использовать Claude Code (скиллы, промпты, режим работы)

### Настройка проекта (день 1)
1. `/init` → затем дописать в `CLAUDE.md`: границы слоёв (запрет импортов «снизу вверх»), правило «промпты только в `skills/`, никаких строковых промптов в `.py`», команды запуска/тестов, что `examples/output` — артефакты, стиль коммитов, язык докстрингов.
2. Установить официальный `pptx`-скилл Anthropic (репозиторий `anthropics/skills`, в нём знания по OOXML/python-pptx): `/plugin marketplace add anthropics/skills` → установить document skills (команды сверить с README репозитория). Он помогает Claude правильно править XML слайдов.
3. Создать **проектные скиллы** в `.claude/skills/` (каждый — `SKILL.md` + скрипт в `tools/`):
   - `pptx-xray` — дамп структуры любого .pptx: лейауты, плейсхолдеры с координатами, гистограммы цветов/шрифтов/кеглей, повторяющиеся фигуры. Claude читает сводку вместо сырого XML.
   - `render-deck` — `soffice` → PDF → PNG в `out/render/<deck>/`, печатает пути. Затем Claude **читает PNG и видит слайд** — главный цикл верификации вёрстки.
   - `audit-deck` — прогон аудита, компактный отчёт.
   - `skill-bump` — новая версия скилла сервиса в `skills/<name>/vN+1/` + запись в changelog реестра.
4. Разрешения (`/fewer-permission-prompts` после пары сессий): `python`, `pytest`, `soffice`, `git`.

### Встроенные скиллы, которые пригодятся
- `design` — макет Streamlit-экранов и слайдов питча до кодинга (быстро согласовать с собой визуал).
- `dataviz` — правила цветов/подписей для графиков в HTML-экспорте и в стилизации native-chart.
- `code-review` / `simplify` — перед каждым тегом и в конце дней 6, 9, 12.
- `security-review` — день 12 (загрузка пользовательских файлов, распаковка zip → проверить path traversal).
- `run` — запуск Streamlit для скриншотов в видео/README.

### Режим работы с Claude (что реально экономит время)
- **Один модуль — одна сессия, начинать с Plan mode** (Shift+Tab). Давать ссылки на конкретные файлы и на `docs/ARCHITECTURE.md`, чтобы не дрейфовал.
- **Сначала контракт, потом код**: pydantic-схемы `TemplateDNA`, `DeckOutline`, `DeckIR`, `AuditReport` пишутся в день 1–4 и фиксируются; все модули пишутся под них.
- **Визуальная верификация**: после любой правки рендера — `render-deck` и просить Claude посмотреть PNG и перечислить дефекты. Это заменяет отсутствующего дизайнера.
- **Тесты как спецификация аудита**: для каждой проверки — синтетический «плохой» слайд в `tests/fixtures/`. Claude генерирует их быстро через python-pptx.
- Коммит после каждого зелёного шага; `git tag` по дням.

### Шаблоны промптов для Claude Code (по фазам)

**Парсинг (день 2)**
> Прочитай `docs/ARCHITECTURE.md` и `core/ir.py`. Реализуй `parsing/extract_tokens.py`: на вход .pptx, на выход `TemplateDNA.tokens`. Цвета и шрифты извлекай из фактического использования на слайдах/лейаутах/мастере (гистограммы через lxml), а не только из theme.xml — в датасете тема не совпадает с реальностью (см. вывод `tools/pptx_xray.py` для VK WorkSpace). Роли цветов (background/text/accent/muted) назначай по площади фигур и по контрасту. Типографическую шкалу кластеризуй по кеглям с ролями. Напиши pytest на 4 шаблона из `data/templates/` с проверкой, что основной шрифт — Play/Montserrat и accent — #0077FF/#FF0053.

**Классификатор архетипов (день 3)**
> Реализуй `parsing/layout_classifier.py`: по плейсхолдерам/фигурам слайда (тип, bbox в долях слайда, количество текстовых блоков, наличие pic/chart/table) определи архетип из enum в `core/ir.py`. Сначала детерминированные правила, затем для неоднозначных — VLM через `skills/template_tagger/v1/prompt.md` (промпт положи в файл, не в код). Выведи таблицу «слайд → архетип → слоты» по всем 4 шаблонам, я проверю глазами.

**Рендер (день 5)**
> Реализуй `render/pptx_writer.py`: клонирование слайда-образца (копия XML `p:cSld` + rels, включая картинки/медиа) в новую презентацию на базе того же файла шаблона (удалить все исходные слайды, оставить мастера/лейауты/тему), заполнение слотов из `DeckIR`. Не растеризовать ничего. После реализации прогони `render-deck` и опиши, что видишь на PNG.

**Аудит (день 8)**
> В `audit/deterministic/` реализуй проверки из `docs/AUDIT.md` (таблица id → описание → слой). **Три варианта (день 7)**

Сгенерируй 3 варианта на одном контенте и шаблоне, отрендери, сравни визуально и опиши различия — этот текст пойдёт в ARCHITECTURE как обоснование оси различий.

**Документация (день 12)**

**Питч (день 13)**
