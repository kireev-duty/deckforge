# AUDIT — проверки сгенерированных слайдов

Аудит — часть пайплайна: `render → детерминированный аудит → безопасные автофиксы → re-render → повторный аудит
→ PNG → VLM-судья`; остальные фиксы предлагаются пользователю в UI.
Детерминированные проверки работают по XML .pptx / DeckIR (координаты, цвета, шрифты) и всегда дают один результат.
Контекстуальные — выполняются VLM по PNG слайда (скилл `audit_judge`), результат может отличаться между запусками.

Каждая проверка возвращает `Finding(check_id, kind, severity, slide_idx, element_id, box, message, autofix, evidence)`;
`box` подсвечивается в UI, `autofix` — имя из каталога `core/autofix.FIXES` (см. «Автофиксы»), `evidence` — числа для объяснения.

Запуск: `deckforge audit <deck.pptx> -t <template.pptx> [--ir deck.ir.json] [--checks L03,T06] [--contextual [--png-dir dir]
[--outline outline.json] [--content-pack dir]] [--fix-plan] [--json out.json]`.
В `deckforge run` аудит выполняется автоматически по `audit:` в конфиге (`deterministic`, `autofix`, `contextual`;
`--no-fix` / `--no-judge` выключают из командной строки): `<strategy>.audit.json` — итоговый отчёт (детерминированные
после фиксов + контекстуальные), сводка в `manifest.json["audit"]` (в т.ч. `autofix.before/after/items`) и колонка
«аудит err/warn» в `compare.md`. CLI-аудит колоду не меняет — фиксы применяются только внутри `run`.

## Как устроено (`deckforge/audit/`)

- `context.py` — колода читается один раз через `core/deck_reader.py` (общий читатель фигур с HTML-экспортом; резолв наследования шрифтов/цветов — `core/package.py`, тот же, что в парсинге). Каждая фигура → `ShapeRec`: абсолютный bbox, абзацы и run'ы с резолвленными шрифтом/кеглем/цветом, выравнивание и маркеры, заливки (с альфой), `bodyPr` (insets, wrap, anchor, autofit), геометрия (prstGeom, поворот, флипы), детали картинки (px, srcRect, часть в zip), диаграммы (серии, легенда, подписи осей, данные категорий/значений) и таблицы (строки, колонки, ячейки с заливками и объединениями). `AuditContext` добавляет флаги `is_slot / is_fixed / is_ours / is_decor` по DNA и IR.
- Вход — `TemplateDNA` (`parsing/dna.build_dna`: токены + сетка + фиксированные элементы + образцы) и, если есть, `DeckIR`.
  - **С DeckIR**: известно, из какого образца слайд, какие слоты заполнены нами (`is_ours`), что фиксировано (`is_fixed`), что декор образца (`is_decor` — картинки вне слотов). Проверки шаблонности (T02, T03) смотрят только на *наши* фигуры: декор образца по определению в палитре, а токены усечены.
  - **Без DeckIR** («чужая» колода): все не фиксированные контентные фигуры — наши; T05 работает по `dna.fixed_elements`; D05/I03 считают слайд с ≤ 2 блоками титульным.
- Контентный блок (`is_content`) — текст с содержимым, картинка в слоте, диаграмма, таблица; не колонтитулы, не декор.
- Геометрия, унаследованная от образца (бокс совпадает с боксом слота), — дизайн шаблона: такие находки получают `warning` и `evidence.in_exemplar=1`, а не `error`.
- Метрики текста (`text_metrics.py`) — Pillow по TTF; Play/Montserrat в системе нет, меряем по Arial с поправкой ширины (`WIDTH_FACTOR`, Play ≈ 0,9 по замеру рендера). Без TTF — 0,5·кегль на символ.
- Пороги — константы в начале каждого модуля `deterministic/*.py`; менять их, а не тесты.

## Контекстуальные (`deckforge/audit/contextual/judge.py`, скилл `audit_judge@v2`)

Один вызов VLM на слайд, параллельно (`WORKERS = 4`). Вход — PNG слайда + заголовок и текст слайда (из IR: текст
после fitting, диаграммы и таблицы — данными; для чужой колоды без IR — из самого pptx) + заголовки соседей + факты
из контент-пакета (`slides_from_ir`: сначала фрагменты по `OutlineSlide.sources`, затем остальные до 6 000 символов —
`sources` у outline часто неполные, и без этого судья зовёт реальные цифры выдуманными). Исходных материалов может
не быть вовсе (режим «на входе только шаблон» — бриф выводится из него): блок фактов тогда пуст, и C04 проверяет
самосогласованность колоды, а не совпадение с источником. Ответ модели —
`{"answers": {"C01": {"ok", "note"}}}`; «нет» → `Finding(kind="contextual")`, `ok=true` и `n/a` — находки нет.
Сбой вызова даёт `C00_judge_error` (info) на слайд, а не падение аудита; та же info-находка «не проверен — бюджет
времени» у слайдов, до которых судья не дошёл к дедлайну прогона (`RUN_TIME_BUDGET_S`, общий для трёх колод). Для title / section / closing вопросы
C01, C02, C03, C05, C11 не считаются (на разделителе «Контекст» судья честно отвечает «пустой слайд»). Автофиксов
у контекстуальных находок нет — они для пользователя.

| check_id | Вопрос | Severity |
|---|---|---|
| C01_title_insight | Заголовок содержит вывод, а не просто называет тему? | warning |
| C02_content_matches_title | Содержимое слайда соответствует заголовку? | error |
| C03_one_message | Слайд пересказывается одним предложением? | warning |
| C04_facts_consistent | Цифры и утверждения непротиворечивы (и не спорят с исходниками, если они переданы)? | error |
| C05_has_content | На слайде есть содержание, а не только заголовок? | error |
| C06_images_relevant | Картинки и иконки относятся к теме слайда? | warning |
| C07_no_garbage | Нет служебного мусора: реплик спикера, кусков промпта, заглушек? | error |
| C08_no_typos | Текст без опечаток? | warning |
| C09_one_language | Текст слайда на языке колоды? | warning |
| C10_table_legend_relevant | Все строки таблицы и элементы легенды работают на мысль слайда? | info |
| C11_flow | Слайд логически связан с соседними (по заголовкам)? | warning |

Что судья нашёл на реальной колоде (VK Tech, narrative, 15 слайдов за 33 с, ≈22k токенов, кассета
`tests/cassettes/audit_judge_pulse.json`): многоточия после обрезки текста fitting'ом (C07 — на самом деле сигнал,
что текст не влез и был укорочен); цифры, спорящие с переданными `sources` (C04, лечится добором фактов);
одинаковые заголовки у KPI-слайдов, разбитых планировщиком (C11); слайд с метриками, не подтверждающий тезис
заголовка (C02). Ложные: «пустой» разделитель (исключено), «n/a» как «нет» (исключено).

## Автофиксы (`core/autofix.py` — каталог, `layout/autofix.py` — применение)

`Finding.autofix` — имя из `FIXES`; у каждого фикса `scope` и `safe`:

| как | что | фиксы |
|---|---|---|
| **safe** — `run` применяет сам при `audit.autofix: true` | правка `DeckIR`, не теряет смысл и структуру | `shrink_font_by_scale` (L03: кегль × √(есть/нужно) по высоте, линейно по ширине, не ниже 70 % от образца / 40 % для KPI-цифры; если порога мало — хвост по смысловому разделителю (`fitting.cut_tail`), у прочего текста затем по словам; заголовок по словам не режется — снимается последнее придаточное, «(1/2)» сохраняется, а без разделителя заголовок остаётся как есть и error честно остаётся → replan), `snap_font_size` (T02: к ближайшему кеглю шкалы, только в пределах ±25 % и не для KPI-цифр), `snap_color` (T03: наш цвет → ближайший из палитры; T06 сюда не попадает — у него нет `nearest`), `refill_slot` (D02: пункт до 15 слов по разделителям — кроме цитат; I02: абзац-заглушка удаляется), `add_chart_labels` (I05: подписи данных + подпись оси из `y_label`), `drop_shape` |
| **ir** — по выбору пользователя (UI, `plan_fixes(report, [номера находок])`) | правка `DeckIR`, теряет контент | `drop_slide` (I03/I06, с перенумерацией), `drop_minor_series` (D04: 5 крупнейших серий) |
| **replan** — только предложение | нужен пересбор состава или другой образец | `split_slide`, `split_table`, `change_exemplar`, `reflow_vertical`, `clamp_to_slide`, `snap_to_grid`, `crop_to_aspect`, `restore_fixed`, `reset_font` |

Не чинятся никогда: находки с `evidence.in_exemplar` (дизайн шаблона), уровня `info` (T02 «подгонка 70–100 %» —
это осознанный fitting) и без нужных полей `evidence` (`FixSpec.requires`). Нативные chart/table получают в файле
новый id — элемент IR для них ищется по совпадению бокса. `apply_fixes` работает над копией IR и возвращает журнал
`applied` / `skipped` (с причиной) — он попадает в `manifest["audit"]["autofix"]["items"]`. Один проход: после фиксов
колода рендерится заново и аудит повторяется; `before`/`after` в manifest. На VK Tech безопасные фиксы снимают все
наши `error` (1–2 L03 на колоду), `warning` остаются (T06 muted-серый из палитры, L02 из образца).

Правило добавления фикса: запись в `FIXES` → обработчик в `layout/autofix._HANDLERS` → тест в `tests/test_autofix.py`
«после фикса и повторного рендера проверка чиста».

## Покрытие тестами

Покрытие: 24 проверки (L01–L07, T01–T06, D01–D05, I01–I06) = 24 фикстуры-нарушения + чистая колода; читатель фигур — `tests/test_deck_reader.py` (данные диаграмм и таблиц совпадают с IR).

- `tests/fixtures/bad_slides.py` — для каждой детерминированной проверки колода-нарушение `make_<ID>()` (python-pptx, генерируется в `tmp_path`) и чистая колода `make_clean()`. Выгрузить глазами: `tools/make_fixtures.py --audit`.
- `tests/test_audit_deterministic.py`: (а) каждая проверка находит своё нарушение на нужном слайде, (б) на чистой колоде ни одна из 24 не срабатывает, (в) битый файл даёт только I01.
- `tests/test_audit_context.py`: `build_dna` и `AuditContext` на VK Tech, полный аудит сгенерированной колоды (без I01/I04/T01/T04/T05).
- `tests/test_autofix.py`: каталог покрывает все имена, которые выдают проверки; каждый safe-фикс на синтетическом IR; `in_exemplar`/info/replan пропускаются с причиной; на реальной колоде VK Tech после safe-фиксов и повторного рендера `error` = 0.
- `tests/test_audit_contextual.py`: разбор кассеты реального прогона, пропуски для структурных слайдов, формы ответа (`"false"`, `n/a`, лишние id), сбой одного слайда → `C00`, контекст слайдов из IR (текст после fitting, данные диаграмм, факты).
- `tests/test_diagrams.py`: схема из автофигур на VK Tech — нативные фигуры и подписи, на её слайде нет error и нет L02/L03/L05/L06/T01/T02/T03.
- `tests/test_pptx_writer.py`: растущая плашка заголовка (ЛЦТ2026), аватар спикера и иконка пустой карточки уходят (VK WorkSpace).
- `tests/test_pipeline.py`: цикл audit → autofix → re-render в `run` (`before` > `after`, L03-ошибок нет), судья через `FakeClient` с PNG (пропускается без LibreOffice).
