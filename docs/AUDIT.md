# AUDIT — проверки сгенерированных слайдов

Аудит — часть пайплайна: `render → audit → autofix → (пользователь выбирает фиксы) → re-render`.
Детерминированные проверки работают по XML .pptx / DeckIR (координаты, цвета, шрифты) и всегда дают один результат.
Контекстуальные — выполняются VLM по PNG слайда (скилл `audit_judge`), результат может отличаться между запусками.

Каждая проверка возвращает `Finding(check_id, kind, severity, slide_idx, element_id, box, message, autofix, evidence)`;
`box` подсвечивается в UI, `autofix` — имя функции в `audit/autofix.py` (день 9), `evidence` — числа для объяснения.

Запуск: `deckforge audit <deck.pptx> -t <template.pptx> [--ir deck.ir.json] [--checks L03,T06] [--json out.json]`
(скилл Claude Code `audit-deck`). В `deckforge run` аудит выполняется автоматически при `audit.deterministic: true`:
`<strategy>.audit.json`, сводка в `manifest.json["audit"]` и колонка «аудит err/warn» в `compare.md`.

## Как устроено (`deckforge/audit/`)

- `context.py` — колода читается один раз через `core/package.py` (тот же резолв наследования шрифтов/цветов, что и в парсинге). Каждая фигура → `ShapeRec`: абсолютный bbox, абзацы и run'ы с резолвленными шрифтом/кеглем/цветом, заливки, `bodyPr` (insets, wrap, autofit), детали картинки (px, srcRect), диаграммы (серии, легенда, подписи осей) и таблицы (строки, колонки, заливки ячеек).
- Вход — `TemplateDNA` (`parsing/dna.build_dna`: токены + сетка + фиксированные элементы + образцы) и, если есть, `DeckIR`.
  - **С DeckIR**: известно, из какого образца слайд, какие слоты заполнены нами (`is_ours`), что фиксировано (`is_fixed`), что декор образца (`is_decor` — картинки вне слотов). Проверки шаблонности (T02, T03) смотрят только на *наши* фигуры: декор образца по определению в палитре, а токены усечены.
  - **Без DeckIR** («чужая» колода): все не фиксированные контентные фигуры — наши; T05 работает по `dna.fixed_elements`; D05/I03 считают слайд с ≤ 2 блоками титульным.
- Контентный блок (`is_content`) — текст с содержимым, картинка в слоте, диаграмма, таблица; не колонтитулы, не декор.
- Геометрия, унаследованная от образца (бокс совпадает с боксом слота), — дизайн шаблона: такие находки получают `warning` и `evidence.in_exemplar=1`, а не `error`.
- Метрики текста (`text_metrics.py`) — Pillow по TTF; Play/Montserrat в системе нет, меряем по Arial с поправкой ширины (`WIDTH_FACTOR`, Play ≈ 0,9 по замеру рендера). Без TTF — 0,5·кегль на символ.
- Пороги — константы в начале каждого модуля `deterministic/*.py`; менять их, а не тесты.

|---|---|---|---|---|---|---|

Что аудит нашёл на реальных колодах (VK Tech, holdout ЛЦТ2026; сверено с PNG): «42 %» в две строки в KPI-карточке, заголовок шире плашки-подложки, подписи KPI под крупной цифрой (в образце так же → warning), muted-подписи #8F8F8F на белом (3,2:1), пустые body-плейсхолдеры образцов ЛЦТ2026, 17-словная цитата.

## Покрытие тестами

- `tests/fixtures/bad_slides.py` — для каждой детерминированной проверки колода-нарушение `make_<ID>()` (python-pptx, генерируется в `tmp_path`) и чистая колода `make_clean()`. Выгрузить глазами: `tools/make_fixtures.py --audit`.
- `tests/test_audit_deterministic.py`: (а) каждая проверка находит своё нарушение на нужном слайде, (б) на чистой колоде ни одна из 24 не срабатывает, (в) битый файл даёт только I01. Пункт «после autofix повторный аудит чист» — с появлением `autofix.py`.
- `tests/test_audit_context.py`: `build_dna` и `AuditContext` на VK Tech, полный аудит сгенерированной колоды (без I01/I04/T01/T04/T05).
- Контекстуальные проверки тестируются на записанных ответах модели (`tests/cassettes/`).
