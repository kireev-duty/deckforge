## Контекст

2 недели, стек Python (FastAPI) + Streamlit, инференс через внешний API (открытые модели ≤35B, Apache 2.0/MIT). Нужно сдать: репозиторий, документацию (README / ARCHITECTURE / MODELS / AUDIT), питч (≤7 мин, шаблон ЛЦТ2026), работающий прототип, видео-демо и 9 презентаций (1 контент × 3 шаблона × 3 варианта вёрстки).

Архитектура по факту — `docs/ARCHITECTURE.md`, правила работы с кодом — `docs/DEVELOPMENT.md`, открытые пункты — `docs/BACKLOG.md`.

## Уточнения организаторов (чат кейса)

- Все материалы — продукт и презентация — загружаются на платформу.
- Время генерации **одной** колоды ≤ 5 минут; попасть в 5 минут нужно независимо от инференса VK — достаточно уложиться по внешнему API. Отсюда бюджет времени в пайплайне.
- Целевой объём 10–15 слайдов или заданный пользователем — объём пользователя доходит до стратегий (`Strategy.for_target`).
- Текст слайдов генерируется из задачи перед воркфлоу и контекста в нём — у нас бриф + контент-пакет + тип/аудитория.
- Формат и видение различий трёх презентаций — на усмотрение команд; команды **демонстрируют различия, оцениваются различия и их актуальность** — отсюда «для кого» (`audience_hint`) в UI, `compare.md`, питче и ARCHITECTURE.
- На финальной защите презентации генерируются по шаблону, которого команды не видели — сценарий демо на чужом шаблоне (`docs/DEMO.md`).
- Кто делает коммиты — неважно; TTFT/SLA инференса VK не предоставляются.
