# DEMO — сценарий живого прогона и видео-демо (≤ 7 минут, без склеек)

> **Записанное видео-демо (5:43, один дубль):** [смотреть онлайн](https://cloud.mail.ru/public/JFkd/v7Uxs1LRy) · [скачать .mp4](https://github.com/kireev-duty/deckforge/releases/download/v0.1.4/deckforge-demo.mp4) · [сценарий видео](DEMO_VIDEO.md)

Требование ТЗ: видео-демо до 7 минут — запись экрана без монтажных склеек или живой прогон; на вход — **неизвестный шаблон** (контент-пакет — если он есть), на выходе — готовая презентация. Уточнение организаторов: в видео — **без склеек показать, как собираются три варианта**, а не одна презентация. Сценарий так и устроен: одна кнопка, три колоды параллельно, дальше — вкладки вариантов. Тот же сценарий — блок «Демо» в питче (≈ 2 минуты из 7; слайд 9 питча — шпаргалка из пяти шагов).

На защите контент-пакета может не быть вовсе: сценарий ниже идёт по ступени «Бриф и файлы», но первым кадром показывается ступень «Только шаблон» — сервис запускается на незнакомом .pptx вообще без ввода (ARCHITECTURE, «Режимы входа»).

## Подготовка (до записи, в кадр не входит)

1. `.env` с рабочими ключами; `tools\check_env.py` — все пункты `[OK]` (репозиторий, LLM, VLM, T2I, LibreOffice), «Итог: всё в порядке».
2. Шаблон для демо — чужой, не из датасета: `data\wild\шаблон-макет МТУСИ.pptx` (Montserrat встроен, 41 образец, все архетипы, 0 ошибок аудита на трёх стратегиях) или любой .pptx из интернета. Запасной — `data\wild\02_HSE_Presentation_Shablon_en.pptx`.
3. Прогреть кэши, чтобы в кадре не ждать LibreOffice:
   - один раз загрузить шаблон в UI («Свой шаблон .pptx») — он сохранится как `out\ui\templates\<stem>__<sid>.pptx` и останется в списке «📤» после перезапуска;
   - `.venv\Scripts\python.exe tools\render_deck.py "out\ui\templates\<stem>__<sid>.pptx"` → `out\render\<stem>__<sid>\contact.png` — UI ищет миниатюры образцов именно по stem загруженного файла (`ui/app.py`, `show_template`), рендер `data\wild\…` напрямую не подхватится;
   - `.venv\Scripts\python.exe -m deckforge.cli parse "data\wild\<шаблон>.pptx"` — убедиться, что палитра/шрифты/архетипы осмысленны (это же говорится вслух);
   - сухой прогон целиком с судьёй на этом шаблоне: замерить время (≈ 3 мин) и прогреть `out\archetypes\`.
4. Контент-пакет датасета — это только шаблоны, поэтому основной режим демо — «Только шаблон». Для ступени «бриф и файлы» под рукой в проводнике синтетический пакет «Пульс команды»: `examples\content_pack\brief.md` (текст брифа — в поле), `product.md`, `data\metrics.json` (файлы — в загрузчик). В UI есть чекбокс «Добавить пример „Пульс команды“» — можно им, но загрузка файлов в кадре нагляднее.
5. Запустить UI заранее: `.venv\Scripts\python.exe -m streamlit run deckforge\ui\app.py` → `http://localhost:8501`. Окно браузера 1920×1080, масштаб 100 %, боковая панель открыта. PowerPoint установлен и закрыт.
6. Запись: OBS / Xbox Game Bar (Win+G), один дубль. Таймер на втором мониторе или телефоне.
7. Ноутбук — от сети, крышку не закрывать. Пока идёт генерация, сервис сам не даёт системе уснуть и погасить экран (`powercfg /requests` в консоли администратора покажет `python.exe` в DISPLAY и SYSTEM), но закрытая крышка или кнопка питания усыпят его всё равно — а таймауты ожиданий в Windows сон не считают, и прогон выйдет за 5 минут.

## Запасные ходы

- **OpenRouter тормозит / таймаут** (судья 30–150 с на колоду днём, три колоды судятся одновременно): снять чекбокс «VLM-судья» — прогон ≈ 1,5 минуты; судью показать на готовой колоде из `examples/output/*/narrative.audit.json` (контекстуальные находки в «Все находки»).
- **Судья не успел часть слайдов**: в аудите info-находки C00 «не проверен — бюджет времени прогона», в manifest — предупреждение о пропуске. Это и есть работа лимита: колоды готовы в 5 минут, а медленный инференс урезал только судью.
- **LLM не отвечает совсем**: CLI с готовым outline —
  `.venv\Scripts\python.exe -m deckforge.cli run -c configs\run.example.yaml --outline examples\output\vk_tech\outline.json --no-judge --no-images --png -o out\demo` — три колоды ≈ 50 с; показать `out\demo\compare.md` и PNG.
- **Контент-пакета на защите не дали**: режим «Только шаблон» в UI (или `-c configs\template_only.yaml`) — ввод не нужен вовсе, выведенный бриф показывается рядом с вариантами и лежит в прогоне как `brief.md`.
- **Контекст — репозиторий, документация и история** (вводная жюри): режим «Репозиторий» в UI — задача строкой, папка или .zip. Подготовку контекста делать до записи: на deckforge она занимает ≈ 1,5 минуты и кэшируется, в кадре повторная подготовка — секунда («из кэша»). CLI: `prepare-context . -o out\context.json` → `run -c … --context out\context.json --topic "…"`.
- **LibreOffice не найден**: UI предупредит; без PNG/PDF/судьи — показать .pptx в PowerPoint и .html в браузере (не зависят от LibreOffice).
- **Картинки (T2I)** включаются чекбоксом «Иллюстрации (T2I)» (+10–20 с на колоду); если генерация недоступна — снять его и показать `examples/output/vk_tech/` (сгенерированные иллюстрации в `images/`).
- **Текст выступления не успел** (медленный провайдер): в manifest предупреждение «не готов к дедлайну прогона», в аудите N01 на слайдах без текста — колода при этом готова в срок. Показать текст на колоде из `out\notes_check3\` или прогоне без судьи.

## Что должно попасть в кадр обязательно (критерии ТЗ)

1. Загрузка **неизвестного** шаблона и разбор его дизайн-системы.
2. Три варианта на одном контенте; названы режимы входа, включая «только шаблон, без контент-пакета».
3. Аудит: детерминированные находки с подсветкой на слайде, контекстуальные (судья), автофиксы и выбор пользователя.
4. Экспорт .pptx с редактируемыми объектами (клик в диаграмму в PowerPoint), .pdf, .html.
5. `manifest.json` с версиями скиллов/моделей и таймингами.
6. Текст к каждому слайду (вводная жюри): блок «Текст выступления · ≈ N мин из 7» на вкладке варианта, заметки докладчика в PowerPoint, клавиша N в HTML; колонка «речь, мин» в `compare.md`.
